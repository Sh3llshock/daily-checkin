ID Share

Consent-based sharing of government ID documents in healthcare on Ethereum

BCS3210 Blockchains, group project
[Names of the group members]

The problem

  • Every clinic, lab and insurer keeps its own scan of your ID
  • You don't know who has a copy or who looked at it
  • You can't take a copy back
  • No audit trail you can check yourself
  • Every provider is a breach target: Change Healthcare 2024, 192.7 million people affected
  • Patients get nothing back for sharing
2

Our idea

  • ID photos stay with the patient (off-chain vault)
  • On-chain: only hashes, consents and the access log
  • Consent: 1 to 365 days, front / back / both, revocable any time
  • Every access attempt logged, also the failed ones
  • 10 ACT reward token for the first consent to a provider
RoleCan
Patientregister, grant / revoke consent, read log
Requesterrequest access, get allowed photos
Adminapprove requesters, pause

Design decision 1: failed requests must not revert

A revert also rolls back the log entry, so a denied attempt would leave no trace.

requestAccess therefore always writes the log and emits an event, and returns true or false.

if (!approved)  reason = NotApproved;
else if (!exists)  reason = NoConsent;
else if (revoked)  reason = Revoked;
else if (now >= expiresAt) reason = Expired;

granted = (reason == None);
accessLogs[patient].push(...);
emit granted ? AccessGranted
             : AccessDenied(reason);

Design decision 2: the chain is public

  • Our first version returned the file link from the contract, but anyone can read contract storage
  • So the vault enforces access, based on on-chain proof:
  1. Requester calls requestAccess
  2. Sends tx hash + signature to the vault
  3. Vault checks: AccessGranted event, signer, age, not reused, consent still valid
  4. Vault sends only the allowed photos
  5. Requester checks SHA-256 against the chain

Every download has a matching entry in the on-chain audit log.

Limitations and next steps

  • Local chain: on mainnet ~12 s per block and real fees, so move to a Layer-2 rollup
  • Access pattern (who asked whom, when) is public: zero-knowledge proofs could hide it
  • Admin is one trusted party: use a multi-sig
  • A requester can keep copies; the chain proves access but cannot force deletion
  • Encrypt files for the requester, use MetaMask instead of test keys
